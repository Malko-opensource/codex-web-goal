# 연결 구조와 상태 소유권

## 핵심 결론

`연결됨`은 확장 프로그램의 WebSocket이 브리지에 인증되었다는 뜻일 뿐이다. 올바른 대화가
바인딩되었거나 요청이 전달되었거나 로컬 파일이 만들어졌다는 뜻이 아니다. 전체 시스템에 하나의
최종 권위를 두지 않고 상태 종류별 권위를 둔다.

```text
ChatGPT 렌더링 표면 ←→ ConversationSurfacePort ←→ Web Goal 브리지
   ├─ ChromeExtensionAdapter (현재)                    │
   └─ CodexInAppAdapter (호스트 API 필요)              ├→ 로컬 워크스페이스
            │                                           │
            └──── HTTPS 공개 터널 → MCP ───────────────┤
로컬 Codex TUI ← loopback App Server, read only ───────┘
```

## 구성요소별 책임

선택형 web-controlled는 **호스트 대기 연동부**와 **Mac 격리 실행기**를 추가한다. 전자는 모델 호출
스케줄링·사용자 개입을, 후자는 격리·실행 결과를 소유한다. 브리지는 맥락/정책 버전·run·wake를
관리한다. 인앱 브라우저는 이를 대신하지 않는다. [실제 호스트 연결 조건](web-controlled-execution.md)은
미완료 의존성으로 명시하며, 어댑터 인터페이스만으로 무모델 대기 완료를 주장하지 않는다.

| 구성요소 | 소유 상태와 최종 권위 | 소유하지 않는 것 | 장애 시 의미 |
| --- | --- | --- | --- |
| ChatGPT Web | 렌더링된 대화, 도구 호출 진행, Web 답변 | 로컬 파일의 최종 내용, 네이티브 Goal 완료 | 응답이 보여도 파일 반영·검증 완료는 별도 확인 |
| 대화 표면 어댑터 | 대화 URL/뷰 연결, 전송 시도 저널, 렌더링 표면 관찰 | Goal 완료, 파일 검증 | 연결과 대화 바인딩을 별도 상태로 봄; 현재 구현은 Chrome 확장 |
| 공개 터널 | ChatGPT와 MCP 포트 사이의 전송 | 세션·작업·완료 상태 | 터널 health 성공은 MCP 작업 가능성의 일부 증거일 뿐 |
| Web Goal 브리지 | 요청 ID, 전달 저널, 세션 바인딩, 쓰기 grant, 파일 연산 기록, seal/checkpoint | 네이티브 Goal 완료, ChatGPT 서비스 내부 상태 | 전달·권한·증거 상태의 권위자이며 불확실성을 보존 |
| 로컬 Codex TUI | 네이티브 Goal 목적·예산·완료, 로컬 실행 판단 | Web 전달 여부 | 브리지의 최신 전달 상태를 읽은 뒤 종료를 판단해야 함 |
| 로컬 워크스페이스 | 현재 파일 바이트와 파일 존재 여부 | 작업 의도, 전송 여부 | 산출물 존재·내용은 반드시 파일 read-back으로 확인 |

**[요구]** 브리지는 Web 전달·쓰기 권한·증거의 최종 권위이고, 네이티브 Goal은 전체 목적 완료의
최종 권위다. TUI 캐시나 확장 팝업 하나의 표시가 다른 권위자의 상태를 덮어쓰면 안 된다.

## 주요 경계 계약

| 경계 | 계약 | 실패·재시도 의미 |
| --- | --- | --- |
| TUI → 브리지 | 동일 작업은 동일 `request_id`와 동일 본문 | 동일 ID의 다른 본문은 거부; 시간 초과만으로 새 ID 전송 금지 |
| 브리지 → 확장 | 대화 URL, turn ID, marker, 전송 또는 재조정 명령 | 새 탭 ID는 같은 정규화 대화 URL일 때만 자동 재바인딩 |
| 확장 → ChatGPT DOM | 입력 후 실제 전송 버튼 클릭, marker가 사용자 메시지로 나타났는지 관찰 | 클릭 이후 marker가 없으면 `uncertain`; Enter 키 의미에 의존하지 않음 |
| ChatGPT → MCP | `workspace_info`로 범위 확인 후 읽기·쓰기·`worker_finish` | MCP 초기화 성공만으로 작업 가능 판정 금지 |
| 브리지 → 워크스페이스 | 전체 파일 SHA와 연산 ID로 파일별 변경 | 다중 파일 원자성 없음; 각 파일을 다시 읽어 조정 |
| 브리지 → TUI | 전달, worker, seal, checkpoint를 독립 진행 정보로 제공 | 오래된 TUI 요약만으로 세션 종료 금지 |

## 탭 수명주기

**[현재 구현]** 확장은 저장된 정규화 대화 URL로 탭을 다시 찾고, 새 탭 ID를 브리지에 알린다.
새로고침 또는 탭 재생성 중 확장 WebSocket도 끊어진 경우, 재접속 완료 시 같은 URL의 탭을 다시
검증하고 바인딩한다. 다른 대화 URL로의 자동 전환은 허용하지 않는다.

**[실연결 관찰]** 같은 대화 URL이라도 새로고침·탭 닫기 뒤 수동 재연결이 필요했던 사례가 있었다.
따라서 URL 기반 재바인딩은 합성 브라우저 테스트와 별개로 실제 ChatGPT 탭에서 다시 검증해야 한다.

## 인앱 브라우저 배치 대안

Codex 인앱 브라우저는 대시보드·문서·상태를 옆 패널에서 보는 관제 화면으로 사용할 수 있다. 그러나
**[현재 구현]** ChatGPT 작업 탭 어댑터는 Chrome MV3의 `chrome.tabs`, content script, 확장 저장소에
의존한다. 인앱 브라우저가 이 확장을 로드하지 않는 한 작업 탭을 그대로 대체하지 못한다.

브리지 코어는 `ConversationSurfacePort`를 통해 표면 구현과 분리한다. 현재 연결되는 구현은
`ChromeExtensionAdapter` 역할이며, `CodexInAppAdapter`는 아래 계약과 안정된 호스트 API가 확보된 뒤 추가한다.

- 저장된 대화 URL identity와 탭 수명주기 관찰
- 전송 직전 durable journal과 실제 제출 확인
- marker 기반 응답 회수와 재조정
- 인증·화면 검사·민감 로그 마스킹
- 브리지 프로세스가 사용할 수 있는 안정된 제어 API

에이전트 턴에서만 사용할 수 있는 일회성 UI 자동화 기능을 브리지의 상시 프로토콜처럼 가정하지 않는다.
현재 권장 배치는 인앱 브라우저에 로컬 대시보드를 열고, 실제 ChatGPT 대화는 확장이 설치된 Chrome에 둔다.
